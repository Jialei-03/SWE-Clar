# Exhibition feed ingestion

Complete this independently reconstructed Python ingestion component. The HTTP reader and source registration are supplied. Implement `process_exhibition_action(state, action, fetch_text=None)` in solution.py and actual feed parsing in feed_parser.py. The optional adapter receives a source URL and returns raw UTF-8 text; omitting it uses the supplied HTTP reader. A sync action contains source_id and current_date (ISO date), optionally fetched_at. It does not supply parsed items. State contains sources and exhibitions dictionaries; return a new JSON-compatible state with result or an error.code.

The basic JSON wire format is an array of objects with title, start_date, end_date, url and optional image. Relative links resolve against the source URL. Source registration fields are source_id, museum, city, url and feed_type, with optional last_fetch. A synthetic JSON example is included. All fixture identities are fictional. Tests supply raw documents and a loopback HTTP server; no customer websites or Notion account are accessed. This is a feed ingestion and view-data component, not a claim that a live Notion workspace or user interface was delivered.

Supported wire formats are public integration information. RSS uses `rss/channel/item` with `title`, `link`, `start_date`, `end_date`, and optional `image` child text. ICS uses `VCALENDAR/VEVENT` with `SUMMARY`, `URL`, `DTSTART;VALUE=DATE` and exclusive `DTEND;VALUE=DATE`, plus optional `IMAGE`; unfold continuation lines and decode escaped text. HTML uses `article.exhibition`, nested `h2` title text, `a.details` href, `time[data-field=start_date/end_date]` datetime and optional `img` src. JSON uses the array schema above. Unsupported/manual sources return `manual_entry_required=true` and `updated=0` without fetching.

Exhibition IDs must be stable, but their encoding is not prescribed. Resolve links against the source URL and preserve URL path case. Status values are `upcoming`, `ongoing`, `closing_soon`, or `closed`; ask the client for the closing-soon policy and required view selection.

Exact state/output agreement: `exhibitions` is keyed by stable exhibition ID; each record includes `source_id` and the documented display fields. A duplicate `exhibition_id` field inside a record is optional. On a successful supported sync set `last_fetch` to supplied `fetched_at`, or to `current_date` when it is omitted. Normal sync returns `result: {updated: n}`; `manual_entry_required: false` may be included but is not required. For manual/unsupported feeds both `manual_entry_required: true` and `updated: 0` are required. Strip surrounding whitespace from URL and image-link inputs before relative resolution; retain path case, query and fragment. This is wire-format normalization, not a change to the client’s business selection policy.

Run from `/workspace` in the provided Python environment. Run `python /public_tests/test_public.py` for existing source-registration and HTTP-reader regression checks. No package installation or external account is required. The benchmark verifies loopback networking and standard-library parsers before the coding budget. This component is a Python library: import `process_exhibition_action` from `solution`; it does not require a persistent application server. Each action returns the next state. Start a fresh scenario with `{"sources": {}, "exhibitions": {}}`. Tests create and stop their own synthetic HTTP endpoints automatically.
