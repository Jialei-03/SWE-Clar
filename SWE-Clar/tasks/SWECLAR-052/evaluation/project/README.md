# Local smartlink integration

Work directory: `/workspace`. Python 3.12.3 is preinstalled by shared python-web-services environment; use standard library only, no package downloads. CPU 2, RAM 2 GiB, process limit 256, temporary disk 512 MiB, network restricted to local prepared services. Build: `python -m compileall -q .`. The benchmark starts the prepared service on port 8090 before the task budget. For a standalone checkout, start it with `python local_service.py`. Health: `curl http://127.0.0.1:8090/health`. Public tests: `python /public_tests/smoke.py`. CLI: `python cli.py < example.json`. Reset: stop local service and restart; pass fresh state for each attempt. Prepared service log: `/tmp/smartlink-provider.log`; standalone service/CLI logs go to stderr. No external account is needed.

Implement `process_smartlink_event(state,event,service=None)` plus `SmartlinkClient.authorize(code)` and `.send_conversion(platform,payload,key)`. Preserve input objects. State maps: smartlinks, oauth_states, spotify_users, clicks, streams, conversions. Attribution window is seconds (default 604800), supplied as a positive finite number. Events: oauth_start(user_id,state_token), oauth_complete(state_token,code), click(click_id,smartlink_id,destination,timestamp), stream(stream_id,click_id,user_id,timestamp), conversion(event_id,platform,stream_id), status(). IDs are nonempty strings; timestamps are seconds. Errors are `error.code`, successes are `result`; successful operations clear prior errors. The CLI processes events sequentially and prints final state. Existing status and OAuth initiation must remain working.

Authorization rejects absent, mismatched or consumed state and non-string/blank code before network access. Use form POST grant_type=authorization_code, code, redirect_uri with HTTP Basic authentication, then GET profile using Bearer access token. Authorize and consume state only after profile has a nonempty id. Store authorized and provider_user_id under the local spotify_users entry. Failures use authorization_failed; invalid callbacks use invalid_oauth_callback. Never put raw codes, secrets or access tokens into returned state. Additional click, stream, conversion and retry decisions are available from the synthetic client.

Configuration fields: token_url, profile_url, client_id, client_secret, redirect_uri, conversion_urls mapping. Local endpoints: `/token`, `/me`, `/meta`, `/tiktok` on http://127.0.0.1:8090. Development-only credentials: local-client / local-secret, code local-code, redirect_uri http://127.0.0.1:8090/callback. These are fabricated fixtures. Real credentials remain in client configuration only. The response from authorize is a profile dict; send_conversion returns decoded connector JSON. HTTP timeout must be bounded. Stream observations are trusted synthetic input, not live listening verification. This is a component extension; web UI, production traffic, vendor-native advertising APIs and live provider integration are outside scope.
