# WordPress directory repair

Independent WordPress 6.8.3 plugin, verified with PHP 8.3, MariaDB 11.4.5 and web-vitals 4.2.4. Install this folder as wp-content/plugins/synthetic-directory and activate directory.php in a private local test installation. The component pages are /?directory_page=members and /?directory_page=about. The fixture uses WordPress options directory_members (records with id,name,group_code,activity_count), directory_content_version and directory_render_count. The render counter is diagnostic and records real uncached component renders.

Complete the directory's cache and field normalization while preserving the working WordPress hooks, pages and assets. CSS/scripts should use native WordPress enqueue APIs. Fixture content and layouts are synthetic; do not import customer themes, plugins, member lists, screenshots, URLs or credentials. This is a directory/plugin component rather than a recreation of the customer's entire site.

The bundled web-vitals library observes actual browser LCP, INP and CLS. window.directoryReadiness evaluates a values object in milliseconds for LCP/INP and unitless CLS. Missing/invalid observations remain missing, not zero. The local test harness may add a controlled interaction workload to obtain measurable event timing. Such short lab observations and a cache hit do not establish field performance or production readiness. Exact thresholds, transient schema, fixture records and instrumentation are disclosed benchmark choices. Real WordPress rendering/asset loading is required; returning flags is insufficient.

The prepared single-container profile includes WordPress 6.8.3, PHP 8.3, MariaDB 11.4.5 and Chromium. Before the task budget, protected preflight creates an independent database, activates this plugin and starts the local page server at http://127.0.0.1:8080. Edit the existing plugin files here and reload the page. `python /workspace/dev_runtime/start.py` checks the running service and prints its address; `python /public_tests/test_public.py` tests the existing pages/filter. Session-scoped runtime files live outside the deliverable or under Git-ignored `runtime/`; a fresh prepared session resets them. No Docker daemon or external network is available to the candidate. Resources: 2 CPUs, 2 GiB RAM, 256 processes. WordPress, MariaDB and their licenses remain in the reusable image; vendor retains the web-vitals Apache-2.0 license.

Metric policy is checked using fixed values at and around the disclosed boundaries. Separately, an actual Chromium page is compared with independent PerformanceObserver entries using a synthetic 60 ms interaction workload and an induced layout shift. Actual observations may exceed the example thresholds without failing the repair; the page must report the resulting decision correctly. Unsupported/missing native workload evidence is an environment issue, not a fabricated zero observation. Additional result metadata and ordering of metric-name lists are permitted.
