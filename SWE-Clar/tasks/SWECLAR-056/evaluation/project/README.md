# Device WebSocket router

Work directory `/workspace`. Node.js 22 and ws 8.19.0 are preinstalled in the benchmark shared environment; no npm install or external accounts required. Only Node built-ins and ws are needed. Build/check: `node --check server.cjs && node --check auth.cjs && node --check broker.cjs`. Start: `JWT_SECRET=local-development-key PORT=8080 node server.cjs`. HTTP health: `http://127.0.0.1:8080/health`; WebSocket: `ws://127.0.0.1:8080/socket`. Public regression: `node /public_tests/smoke.cjs`. Logs use stdout/stderr. Reset: stop and restart with a fresh workspace/session. CPU2, RAM2GiB, process limit256, loopback-only networking. A fresh synthetic secret is supplied separately to each evaluation.

Preserve the HTTP health endpoint and actual WebSocket flow; finish auth.cjs and broker.cjs. Other source files can be changed while retaining the interface. `startServer({secret,clock,port,host})` returns `{port,sweep(timeout),snapshot(),close()}` (async startup/close). clock returns Unix seconds and defaults to wall time; evaluation injects deterministic time. `sweep` takes a positive finite number of seconds; report an error for invalid timeouts. Connect with `Authorization: Bearer <JWT>` using HS256 claims `sub`, `device_id`, `exp`. Successful ready JSON contains type=ready, connection_id and device_id. Malformed JSON or a non-object JSON value receives error.code=invalid_message. Invalid JWT upgrades are HTTP401; duplicate active device in ordinary connect mode is HTTP409.

JSON frame shapes: heartbeat `{type:"heartbeat"}` receives `{type:"heartbeat"}` acknowledgment; publish `{type:"publish",target_device,payload}` receives `{type:"published",sequence}` and routes `{type:"message",sequence,source_device,target_device,payload}`; status `{type:"status"}` returns `{type:"status",active,disconnected,routed_messages,reconnects}`. `snapshot()` returns the same counters without requiring type. Extra metadata is allowed; these fields must keep their meanings. `sweep(timeout)` returns connection IDs. Query `mode=reconnect` requests reconnection handling. Clarify replacement, timing, routing and monitoring rules before implementing them. No user-to-device ownership policy is implied beyond authenticated device sessions; all test identities are synthetic. This independently rebuilt protocol component does not certify production capacity, original device compatibility or full business backend behavior.
