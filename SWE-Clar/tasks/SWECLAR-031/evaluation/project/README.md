# Browser practice chart

Repair a local music practice component with actual MIDI parsing, a timed treble-staff preview, recording playback, synthesized playback and MIDI/PDF exports. Synthetic recordings and MIDI files are generated by the benchmark before the coding budget. The task does not require original music, a proprietary player, external accounts, native app packaging or professional rhythmic engraving.

The prepared environment provides Python, Node, FFmpeg, Chromium, esbuild, @tonejs/midi and pdf-lib. Run from `/workspace`; dependencies are already available through `NOTATION_NODE_MODULES` and `ESBUILD_BINARY_PATH`. Do not install dependencies or generate missing assets during the task.

- Build: `node build.mjs runtime/dist`
- Serve: `PORT=8080 python serve.py runtime/dist`
- Open: `http://127.0.0.1:8080`
- Public tests: `python /public_tests/test_public.py`
- Reset generated build: stop the server, delete `runtime/dist`, then rebuild. Preserve the supplied runtime/config.json, demo.mid and demo.webm.

`runtime/config.json` contains `charts:[{id,title,midi,recording}]`; MIDI/recording paths are local paths relative to the project root. The build copies them and the config into its output. Source inputs must remain unchanged when changing the accepted transposition. The recording is WebM with synthetic video and audio. The server supports byte ranges for seeking. Browser actions require a user gesture.

Preserve the public controls and their IDs: chart selector, recording video, score SVG, pitch-list, transpose integer input, mode selector (recording/synth), play/pause, seek numeric input, position output, midi-export/pdf-export, and error feedback. The existing SVG contains five staff lines and per-note groups with filled heads; retain machine-readable note order and geometry for the timed preview. Colors, typography, overall scaling and placement may change. This interface is part of the provided engineering scaffold, not a hidden client preference.

Keep the recording and staff centered without horizontal overflow on phone, tablet and desktop widths. Render correct staff positions and readable pitch labels. Clarify transposition, playback transitions and current-score export behavior. MIDI/PDF are real downloadable files; implementation style and PDF vector/raster encoding are not prescribed.

All examples are independently generated. Resource policy: 2 CPUs, 2 GiB RAM, 256 processes, 512 MiB workspace, loopback network only. Build and service logs appear in their terminal. Infrastructure preparation is the benchmark's responsibility.
